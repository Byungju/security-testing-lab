# TP-EXT-001-01 Network Reachability Verification Procedure

## Test Procedure ID

TP-EXT-001-01

## Related Objective

DO-EXT-001 Network Reachability Identification

## Related Test Case

TC-EXT-001-01 Network Reachability Verification

- 이 Procedure는 `TC-EXT-001-01`을 실제로 수행하기 위한 절차이다.
- 연결 관계: DO-EXT-001 → TC-EXT-001-01 → TP-EXT-001-01.

## Title

Network Reachability Verification Procedure

## Purpose

- 대상 Linux Server가 평가 위치에서 네트워크적으로 도달 가능한지 확인하기 위한 수행 절차를 정의한다.
- 관찰된 도달성 결과와 그 조건을 기록하여, 이후 Actual Result와 Assessment Result로 이어지게 한다.

## Scope

- 포함: 지정된 대상 네트워크 주소에 대한 외부 관점의 도달성 관찰과 그 기록.
- 제외: 포트·서비스 식별, 취약점 평가, 보안 구성 평가, Unknown Target에 대한 광범위한 Network Discovery.

## Preconditions

- 대상이 승인된 평가 범위에 포함되어 있고 Known Target으로 정의되어 있어야 한다.
- 평가 위치(외부 관점)가 정의되어 있어야 하며, 승인된 네트워크 경로에서 수행되어야 한다.
- 대상 네트워크 주소가 명확해야 한다.
- 수행자가 평가 승인 사실을 확인할 수 있어야 한다.
- 사용할 도구나 명령이 있다면 승인 범위 내에 있어야 한다.
- 실행 환경에 사용할 도구가 존재하고, 필요한 권한이 확보되어 있어야 한다.
- Evidence를 저장할 위치와 형식이 준비되어 있어야 한다.

## Procedure Steps

아래 단계를 순서대로 수행한다. 각 단계에서 관찰한 내용과 Evidence를 함께 기록한다.

| Step | Action | Observation | Evidence |
| --- | --- | --- | --- |
| Step 1 | Preconditions, Target, Assessment Perspective를 확인한다. | 대상 주소, 평가 위치, 승인 상태. | 대상 주소, 평가 위치, 승인 참조. |
| Step 2 | 승인된 방식으로 도달성을 관찰한다(예: ICMP 기반, TCP 연결 기반 등). | 응답 여부, 연결 여부, 오류·거부·타임아웃, 시도 횟수. | 원본 관찰 결과, 시각, 사용한 방식. |
| Step 3 | 필요하면 다른 승인된 방식으로 추가 관찰한다. | 방식별 응답/비응답. | 방식별 원본 결과, 시각, 사용한 방식. |
| Step 4 | 관찰 결과를 도달성 범주로 분류한다. | 관찰됨/관찰되지 않음/제한됨/불충분. | 분류 근거와 원본 결과. |
| Step 5 | Evidence를 보존하고 완료 조건을 확인한다. | 종료 가능 여부. | Evidence 목록, 종료 판단. |

- 특정 도구나 명령을 강제하지 않는다. 사용한 방식과, 사용했다면 도구·명령을 Evidence에 기록한다.

### Step 1 세부

- 승인된 평가 범위에서 대상 주소를 확인한다.
- hostname과 IP 주소가 함께 주어지면 두 값이 같은 대상을 가리키는지 확인하고, 불일치 시 기록하고 진행 여부를 판단한다.
- 여러 주소가 지정되면 주소별로 구분해 기록한다.
- 외부 관점(External Discovery)에서 수행함을 확인하고, 평가 위치를 기록한다.
- 관점이 외부가 아니거나 승인 범위를 벗어나면 수행을 중단하고 기록한다.

### Step 2 세부

- 승인된 방식(예: ICMP 기반, TCP 연결 기반)으로 각 대상 주소에 대해 도달성을 관찰한다.
- 각 시도에서 응답/연결 여부, 오류·거부·타임아웃, 시도 횟수와 시각을 기록한다.
- 사용한 방식과, 사용했다면 도구·명령을 기록한다.
- 응답이 없더라도 도달 불가로 단정하지 않고 관찰 사실로 기록한다.

### Step 3 세부

- Step 2의 결과가 관찰되지 않음, 제한됨, 불충분이면 승인 범위 내에서 다른 승인된 방식으로 추가 관찰한다.
- 방식별 결과를 구분해 기록하고, 방식 간 결과 차이(예: ICMP 미응답 + TCP 응답)를 기록한다.
- 추가 관찰이 승인 범위를 벗어나면 수행하지 않고 그 사유를 기록한다.

### Step 4 세부

- 주소별·방식별 관찰을 Observation Points 범주로 분류한다.
- 분류의 근거가 된 원본 결과와 시각을 함께 기록한다.
- 범주를 정할 수 없으면 inconclusive로 기록한다.
- 이 분류는 관찰 결과의 정리이며, Objective/Expected Result에 대한 평가가 아니다.

### Step 5 세부

- 모든 Evidence를 지정된 위치에 보존하고 목록화한다.
- Evidence가 Target, Assessment Perspective, Timestamp, 수행 내용, 사용한 Tool, 실행 조건, 관찰 결과, 원본 결과를 포함하는지 확인한다.
- Completion Criteria의 충족 여부를 확인하고 종료를 기록한다.

## Observation Points

도달성은 다음 범주를 구분해 관찰·기록한다.

- ICMP Echo 응답이 확인됨.
- ICMP Echo 응답이 확인되지 않음.
- 다른 승인된 통신 방식(예: TCP 연결)으로 접근 가능함이 확인됨.
- 특정 방식만 차단/제한됨(예: ICMP는 응답하지 않지만 TCP는 응답).
- 통신이 확인되지 않음(네트워크 경로 문제 가능성 포함).
- 관찰이 불충분하여 판단할 수 없음(inconclusive).

- ICMP 응답 여부를 Network Reachability 전체와 동일시하지 않는다.
- 응답이 확인되지 않았다는 사실만으로 "도달 불가능"이라고 기록하지 않는다.
- "경로 문제로 인한 실패"와 "정책/필터로 인한 차단"은 서로 다른 원인일 수 있으므로 구분해 기록하되, 이는 관찰·추정으로 기록하고 확정하지 않는다.
- 여러 대상 주소가 있으면 어떤 주소에서 어떤 관찰이 있었는지 주소별로 구분해 기록한다.

## Evidence Collection

| Step | Evidence |
| --- | --- |
| Step 1 | 대상 주소, 평가 위치, 승인 참조, 확인 시각. |
| Step 2 | 사용한 방식, 사용한 Tool, 실행 조건(옵션·파라미터), 시도 결과, 오류·거부·타임아웃 여부, 시각, 원본 관찰 결과. |
| Step 3 | 추가 방식의 사용 여부, 사용한 Tool, 실행 조건, 시도 결과, 시각, 원본 관찰 결과. |
| Step 4 | 도달성 분류와 그 근거가 된 원본 결과. |
| Step 5 | Evidence 목록과 종료 판단. |

- Evidence는 이후 Actual Result와 Assessment Result를 재검토할 수 있는 수준으로 남긴다.
- Evidence는 "명령어 출력"으로만 한정하지 않는다.
- Evidence는 최소한 다음을 추적할 수 있어야 한다.
  - Target
  - Assessment Perspective
  - Timestamp
  - 수행 내용
  - 관찰 결과
  - 원본 결과

## Expected Observation

- 대상 주소에 대한 도달성 관찰 결과와 관찰 조건이 기록된다.
- 어떤 평가 위치에서 어떤 방식으로 도달성을 관찰했는지 기록된다.
- 응답이 관찰되지 않은 경우, 그 사실과 관찰 조건이 구분되어 기록된다.
- 관찰 결과가 도달성 범주 중 하나로 분류된다.

## Completion Criteria

- 승인된 방식(들)에 대한 관찰을 완료하고, 관찰 결과와 Evidence를 기록했다.
- 도달성 범주를 판단할 수 있거나, 불충분하여 inconclusive로 기록했다.
- 다음 중 하나에 해당하면 즉시 종료하고 기록한다.
  - 대상이 승인 범위를 벗어나거나 승인 근거가 확인되지 않음.
  - 예상치 못한 부작용이나 승인되지 않은 영향이 관찰됨.
  - 수행자가 안전하게 계속할 수 없다고 판단함.

## Notes

- 이 Procedure는 특정 도구를 방법론으로 확정하지 않는다. 사용한 방식과 도구·명령은 Evidence에 기록한다.
- 도달성 관찰은 하나의 방식에 의존하지 않는다. Primary 방식과, 필요 시 보조·진단 방식을 함께 사용할 수 있으며, 사용한 방식과 도구를 Evidence에 기록한다.
- 이 Procedure는 결과를 미리 판단하지 않는다. Procedure는 수행·관찰·Evidence 보존까지 담당한다.
- Actual Evidence, Actual Result, Assessment Result, Finding은 실제 실행 단계에서 기록하며, 이 문서에서는 미리 채우지 않는다.
- "Reachable"을 단순히 도구의 응답 여부 하나와 동일시하지 않는다.
- 관련 Technique / Tool: ICMP 기반 도달성 관찰(주 검증, 후보 Tool `ping`), TCP Connect 기반 관찰(선택적 보조 검증, 후보 Tool `nc`), 진단용 Network Path 관찰(후보 Tool `tracepath`). Tool의 상세 설명·사용법은 프로젝트 공통 Tool Catalog(`tools/`, 예: `tools/network/ping.md`, `tools/network/nc.md`)를 참조하며 이 Procedure에 중복 작성하지 않는다.
- TCP 방식은 사전에 지정된 포트에 대한 Reachability 보조 관찰이며, Port Discovery가 아니다. config의 `ports`가 비어 있으면 TCP 검증을 수행하지 않는다.
- 실행 구조: `../execution/`(Configuration과 Runner). Runner는 Execution Result까지만 생성하며 Assessment Result/Finding을 생성하지 않는다.
- 참고: `../objectives.md`의 DO-EXT-001, `../testcases/TC-EXT-001-01.md`, `README.md`.
- NIST Relationship: 이 Procedure는 DO-EXT-001을 계승하며, NIST SP 800-115 Section 4.1 Network Discovery의 개념과 관련된다. Known Target의 도달 가능성 확인 절차는 프로젝트가 평가 흐름에 맞게 구체화한 것이다.
