# TP-EXT-002-01 Network Port Identification (TCP) Procedure

## Test Procedure ID

TP-EXT-002-01

## Related Objective

DO-EXT-002 Network Port Identification

## Related Test Case

TC-EXT-002-01 Network Port Identification (TCP)

- 연결 관계: DO-EXT-002 → TC-EXT-002-01 → TP-EXT-002-01.

## Title

Network Port Identification (TCP) Procedure

## Purpose

- 대상 Linux Server의 지정된 TCP Port Range에 대해 TCP Port State를 식별하는 수행 절차를 정의한다.
- 식별된 일부 포트에 대해 별도의 TCP Connectivity 관찰로 보조/교차검증한다.
- 관찰 결과와 원본 Evidence를 남겨 Actual Result / Assessment Result로 이어지게 한다.

## Scope

- 포함: 승인된 TCP Port Range 스캔, 지정 포트 TCP 연결 관찰, Evidence 기록.
- 제외: 서비스·버전 식별, 취약점/구성 평가, Reachability(DO-EXT-001), UDP, 승인 범위 밖 스캔.

## Preconditions

- 대상이 승인된 평가 범위에 포함되어 있어야 한다.
- 평가 위치(외부 관점)와 승인된 네트워크 경로가 정의되어 있어야 한다.
- 스캔 대상 TCP Port Range와 스캔 허가가 승인되어 있어야 한다.
- 사용할 도구(nmap, nc)가 존재하고 필요한 권한이 확보되어 있어야 한다.
- Evidence를 저장할 위치와 형식이 준비되어 있어야 한다.

## Procedure Steps

아래 단계를 순서대로 수행한다. 각 단계에서 관찰 내용과 Evidence를 함께 기록한다.

| Step | Action | Observation | Evidence |
| --- | --- | --- | --- |
| Step 1 | Preconditions, Target, Assessment Perspective를 확인한다. | 대상 주소, 평가 위치, 승인 상태. | 대상 주소, 평가 위치, 승인 참조. |
| Step 2 | 승인된 TCP Port Range를 확인한다. | 스캔 범위(start-end), 승인 여부. | Port Range, 승인 참조. |
| Step 3 | nmap으로 TCP Port Scan을 수행한다(-sT). | 포트별 상태(open/closed/filtered 등). | 스캔 원본 출력, 사용 방식/도구, 시각. |
| Step 4 | 스캔 결과의 Port State Observation을 수집한다. | 포트/프로토콜/상태. | 스캔 원본 결과. |
| Step 5 | Raw Evidence를 저장한다. | 저장 여부. | 원본 stdout/stderr. |
| Step 6 | (명시적으로 지정된) 특정 포트를 선택한다. | 확인 대상 포트. | 선택 근거(설정값). |
| Step 7 | nc로 해당 포트 TCP Connectivity를 확인한다. | 연결 성공/거부/타임아웃. | 연결 원본 출력, 시각. |
| Step 8 | Connectivity Observation을 수집한다. | 포트별 연결 관찰. | 연결 원본 결과. |
| Step 9 | (필요 시) 후보 open 포트를 저부하 타겟 방식으로 재확인한다(port_reverify). | 재확인 포트 상태. | 재확인 원본 출력, 사용 옵션/도구, 시각. |
| Step 10 | Evidence를 보존하고 완료 조건을 확인한다. | 종료 가능 여부. | Evidence 목록, 종료 판단. |

- Step 6~7의 nc 대상 포트는 Configuration의 `ports`에 명시된 값만 사용한다. Runner가 nmap 결과를 보고 포트를 자동 선택하지 않는다.
- 광역/고속 스캔 결과만으로 포트 목록을 확정하지 않는다. rate-limiting 등으로 누락(false negative)될 수 있으므로, 후보 포트는 Step 9의 저부하 재확인(port_reverify)으로 검증하고 스캔 조건을 기록한다.

## Observation Points

- Port Scan: `open`, `closed`, `filtered`, `open|filtered` 등 Tool이 제공하는 상태.
- TCP Connectivity: 연결 성공/거부/타임아웃.
- 실행 오류: scan error / timeout / execution error.

- Port State를 서비스 존재나 취약점으로 해석하지 않는다.
- nmap과 nc 결과를 동일 의미로 취급하지 않는다(Port State Observation vs Connectivity Observation).
- 스캔 범위 밖 포트는 미검증으로 둔다.

## Evidence Collection

| Step | Evidence |
| --- | --- |
| Step 1 | 대상 주소, 평가 위치, 승인 참조, 시각. |
| Step 2 | Port Range(start-end), 승인 참조. |
| Step 3 | 사용 도구/방식, 포트별 상태, 시각, 원본 스캔 출력. |
| Step 4 | 포트/프로토콜/상태 정리. |
| Step 5 | 스캔 원본 stdout/stderr 보존. |
| Step 6 | 확인 대상 포트(설정값). |
| Step 7 | 연결 결과, 시각, 사용 도구/옵션. |
| Step 8 | 포트별 연결 관찰. |
| Step 9 | 재확인 포트 상태, 사용 옵션/도구, 시각, 재확인 원본 출력. |
| Step 10 | Evidence 목록, 종료 판단. |

## Expected Observation

- 지정된 Port Range의 Port State가 포트별로 기록된다.
- 지정 포트의 TCP Connectivity 관찰이 기록된다.
- 스캔 범위/방식/도구/시각이 기록되고, 범위 밖은 미검증으로 명시된다.
- Port State와 Connectivity가 구분되어 기록된다.

## Completion Criteria

- 승인된 Port Range 스캔과 지정 포트 연결 관찰을 완료하고 Evidence를 기록했다.
- 다음 중 하나에 해당하면 즉시 종료하고 기록한다.
  - 대상/범위가 승인 범위를 벗어남.
  - 예상치 못한 부작용이나 승인되지 않은 영향이 관찰됨.
  - 수행자가 안전하게 계속할 수 없다고 판단함.

## Notes

- 이 Procedure는 결과를 미리 판단하지 않는다. 수행·관찰·Evidence 보존까지 담당한다.
- 포트 스캔은 Raw Evidence를 원본 그대로 보존하며, summary는 사람이 읽는 요약이다.
- Actual Result / Assessment Result / Finding은 실행 이후 단계에서 기록한다.
