# TC-EXT-002-01 Network Port Identification (TCP)

## Test Case ID

TC-EXT-002-01

## Objective

DO-EXT-002 Network Port Identification

- 이 Test Case는 DO-EXT-002를 검증하는 TCP Test Case이다.
- DO-EXT-002는 평가 위치에서 대상 네트워크 주소에 대해 응답하는 TCP/UDP 포트를 식별하는 Objective이다.
- 이번 Test Case는 TCP만 대상으로 하며, UDP는 이후 별도 Test Case로 다룬다.

## Title

Network Port Identification (TCP)

## Purpose

- Assessment Perspective에서 대상 Linux Server의 지정된 TCP Port Range에 대해 TCP Port State를 식별한다.
- 식별 결과를 이후 DO-EXT-003(Service Identification)의 입력으로 사용할 수 있도록 기록한다.

## Scope

- 포함: 승인된 TCP Port Range에 대한 TCP Port State(open/closed/filtered 등) 식별.
- 포함: 식별된 일부 포트에 대한 별도의 TCP Connectivity 관찰(보조/교차검증).
- 제외: 서비스·버전 식별(DO-EXT-003/004), 취약점 평가, 보안 구성 평가, Reachability(DO-EXT-001), 승인 범위 밖 스캔, UDP.
- Port Scan 결과는 Observation이며 보안 판단(위험/취약/불필요)이 아니다.

## Target

- 평가 범위에 포함된 Linux Server의 네트워크 주소(예: hostname 또는 IP 주소).

## Assessment Perspective

External Discovery (외부 관점)

## Preconditions

- 대상이 승인된 평가 범위에 포함되어 있어야 한다.
- 평가 위치(외부 관점)와 승인된 네트워크 경로가 정의되어 있어야 한다.
- 스캔 대상 TCP Port Range와 스캔 허가가 승인되어 있어야 한다.
- nmap(스캔)과 nc(연결 확인) 등 사용할 도구와 필요한 권한이 확보되어 있어야 한다.
- Evidence를 저장할 위치와 형식이 준비되어 있어야 한다.

## Test Method

개념 수준의 검증 의도(Test Intent)이다. 특정 도구를 방법론으로 확정하지 않는다.

- TCP Port Scanning(nmap): config의 `port_range` 전체에 대해 TCP Port State를 식별한다.
- TCP Connectivity Verification(nc): 명시적으로 지정된 일부 포트에 대해 실제 TCP 연결 가능 여부를 별도로 관찰한다.
- nmap 결과를 보고 Runner가 nc 대상 포트를 자동 선택하지 않는다.
- 구체적인 수행 절차는 별도 Test Procedure(`TP-EXT-002-01`)에서 정의한다.

## Expected Result

- 지정된 TCP Port Range에 대한 Port State 관찰 결과와 관찰 조건이 기록된다.
- 스캔 범위와 방식, 사용 도구, 시각, 원본 Evidence가 기록된다.
- 지정된 포트에 대한 TCP Connectivity 관찰 결과가 기록된다.
- 스캔 범위 밖의 포트는 미검증임을 명시한다.
- Port State와 TCP Connectivity 결과를 동일한 의미로 취급하지 않는다.

## Evidence Requirements

- Target: 스캔 대상 주소.
- Assessment Perspective / Location: 어느 평가 위치(외부 관점)에서 관찰했는지.
- Verification Method: TCP Port Scanning / TCP Connectivity Verification.
- Tool: 도구와 버전.
- Execution Conditions: Port Range, 스캔 방식, 옵션, Timeout.
- Observed Result: 포트별 상태(스캔), 연결 결과(연결 확인).
- Timestamp: 관찰 시각.
- Raw Data / Original Observation: 재검토 가능한 원본 출력.

## Actual Result

- 근거 실행:
  - `20261006T145256-DO-EXT-002` (TCP 1-65535, nmap -sT, 공격적 타이밍)
  - 참고: `20261002T153920-DO-EXT-002` (TCP 1-1000)
- 전 범위 스캔 관찰(공격적 타이밍): `22/tcp open`, `23/tcp open`, `filtered 65481`, `closed 52` (open 2).
- 지정 포트 TCP 연결 관찰: `22` timeout, `443` timeout.
- 교차검증: `22`는 스캔 open / 연결 timeout → `discrepancy`. `443`은 스캔 관찰 없음 / 연결 timeout → `no_scan_observation`.
- 참고(스캔 직후 별도 확인): `nmap -sT -p 22,23,512`에서 `22/23/512 open`, `nc 22` 연결 성공(`SSH-2.0-OpenSSH_9.8`).
- 원본: `execution/results/20261006T145256-DO-EXT-002/raw/`, 요약: 동일 디렉터리 `summary.md`.

## Assessment Result

- Expected Result 관점: 지정 TCP Port Range에 대한 Port State와 관찰 조건이 기록되었고, Port State와 TCP Connectivity가 구분되어 기록되었다. 따라서 "식별 수행과 기록" 요구는 충족한다.
- 확인된 범위: 외부 관점, 단일 시점의 TCP Port State 관찰. 확인 대상은 config의 `port_range`(1-65535)이다.
- 확인되지 않은 범위/한계: 공격적 타이밍 스캔은 완전성이 제한된다. 느린 스캔/스캔 직후 재확인에서는 `512`가 open으로 관찰되었으나 전 범위 공격적 스캔에서는 미관찰되었다. nc timeout도 공격적 스캔과 동시에 발생했고 직후 재확인에서는 연결이 성공했다. 즉 스캔 타이밍/속도가 Port State와 Connectivity 관찰에 영향을 준다.
- 평가 근거: 위 Raw Evidence 및 Execution Result(`cross_verification`, `port_state_counts`).
- 종합: "지정 전 범위에서 TCP 포트 상태가 식별되었으나, 사용한 타이밍으로 인한 완전성 한계와 nmap/nc 교차검증 불일치가 관찰되었다." 이는 보안 취약점 판단이 아니라 Objective/Expected Result에 대한 평가이다.

## Finding

- Finding 없음.
- 근거: 관찰(open 22/23/512, 다수 filtered, 타이밍 의존, 교차검증 불일치)은 그 자체로 보안 요구사항 위반을 의미하지 않는다. Finding 판단에 필요한 Security Requirement/평가 기준이 아직 정의되지 않았다.
- 이 Test Case의 결과가 곧 Finding은 아니다.

## Notes

- Port State(open/closed/filtered)는 Observation이며 서비스 존재·취약점을 의미하지 않는다.
- `port_range`는 Port Scan 대상 범위이고, nc의 `ports`는 Connectivity 확인 대상이다. 두 개념을 혼동하지 않는다.
- DO-EXT-001의 TCP connectivity(도달성 보조)와 DO-EXT-002의 Port Identification은 목적이 다르다.
- 참고: `../objectives.md`의 DO-EXT-002, `../procedures/TP-EXT-002-01.md`, `assessments/README.md`의 Test Case Definition 및 Test Execution Model.
- NIST Relationship: NIST SP 800-115 Section 4.2 Network Port and Service Identification의 Port Scanning 개념을 기반으로 한다.
