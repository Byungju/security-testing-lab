# TC-EXT-003-01 Network Service Identification (TCP)

## Test Case ID

TC-EXT-003-01

## Objective

DO-EXT-003 Network Service Identification

- 이 Test Case는 DO-EXT-003을 검증하는 TCP Test Case이다.
- DO-EXT-003은 식별된 각 포트에서 응답하는 네트워크 서비스의 종류를 식별하는 Objective이다.
- 입력은 DO-EXT-002의 결과(응답한 포트 목록)이다.

## Title

Network Service Identification (TCP)

## Purpose

- DO-EXT-002에서 open으로 관찰된 TCP 포트에 대해, 해당 포트에서 동작하는 네트워크 서비스 종류를 식별한다.
- 식별 결과를 이후 DO-EXT-004(Application/Version Identification)의 입력으로 사용할 수 있도록 기록한다.

## Scope

- 포함: DO-EXT-002에서 open으로 관찰된 TCP 포트에 대한 서비스 종류 식별.
- 제외: 애플리케이션/버전 식별(DO-EXT-004), 취약점 평가, 보안 구성 평가, 포트 스캔/도달성(DO-EXT-001/002), UDP.
- 서비스 식별은 Observation이며, 그 자체로 보안 판단이 아니다.

## Target

- 평가 범위에 포함된 Linux Server의 네트워크 주소(예: hostname 또는 IP 주소).

## Assessment Perspective

External Discovery (외부 관점)

## Preconditions

- 대상이 승인된 평가 범위에 포함되어 있어야 한다.
- DO-EXT-002에서 open으로 관찰된 포트 목록이 있어야 한다.
- 서비스 식별 대상 포트가 Configuration에 명시되어 있어야 한다.
- 사용할 도구(nmap)와 필요한 권한이 확보되어 있어야 한다.
- Evidence를 저장할 위치와 형식이 준비되어 있어야 한다.

## Test Method

개념 수준의 검증 의도(Test Intent)이다. 특정 도구를 방법론으로 확정하지 않는다.

- Network Service Identification(nmap -sV): 지정된 각 포트에서 응답하는 서비스 종류를 식별한다.
- 서비스 종류(service)를 기록하며, 버전/애플리케이션 상세는 DO-EXT-004의 범위로 둔다(원본에는 함께 남을 수 있다).
- 대상 포트는 Configuration에 명시된 값만 사용하며, Runner가 임의로 추가하지 않는다.

## Expected Result

- 지정된 각 포트에 대한 서비스 종류(예: ssh, telnet, exec)와 관찰 조건이 기록된다.
- 식별 신뢰 수준(추정/확인)을 구분할 수 있어야 한다.
- 사용한 방식/도구/옵션/시각과 원본 Evidence가 기록된다.
- 서비스 종류가 확정되지 않을 수 있으며, 그 경우 추정/미확인으로 기록한다.

## Evidence Requirements

- Target / Assessment Perspective / Verification Method / Tool(버전) / Execution Conditions(대상 포트, 옵션, Timeout) / Observed Result(서비스) / Timestamp / Raw Output.

## Actual Result

- 근거 실행: `20261006T154323-DO-EXT-003` (TCP 22,23,512,513,514, nmap -sV --version-light)
- 관찰:
  - `22/tcp open ssh` (OpenSSH 9.8 (protocol 2.0))
  - `23/tcp open telnet` (Linux telnetd)
  - `512/tcp open exec?` (`?` = 불확실)
  - `513/tcp open login?` (`?` = 불확실)
  - `514/tcp open tcpwrapped`
  - Service Info: OS: Linux
- 참고(경위):
  - 최초 실행 `20261006T150325-DO-EXT-003`은 ports [22,23,512]만 대상으로 하여 513,514가 누락되었다.
  - 별도 확인에서 `512/513/514`가 open(각 exec/login/shell, nc 연결 성공)임을 확인하여 대상을 `22,23,512,513,514`로 보완했다.
  - 서비스 파싱 정규식이 개행을 넘어 다음 라인을 details로 흡수하는 버그(513 누락)를 발견하여 수정했다.
- 원본: `execution/results/20261006T154323-DO-EXT-003/raw/service_scan/`, 요약: 동일 디렉터리 `summary.md`.

## Assessment Result

- Expected Result 관점: 지정 포트에 대한 서비스 종류와 관찰 조건이 기록되었고, 신뢰 수준의 차이(`exec?`, `login?`, `tcpwrapped`)가 구분되어 기록되었다. 따라서 서비스 식별과 기록 요구는 충족한다.
- 확인된 범위: 외부 관점에서 22/23/512/513/514 포트의 서비스 종류.
- 확인되지 않은 범위/한계: 애플리케이션/버전 상세는 DO-EXT-004 범위이며, 본 결과에서는 서비스 수준까지만 평가한다. 대상 포트는 DO-EXT-002 관찰 + 재확인으로 확정한 목록으로 한정된다.
- 평가 근거: 위 Raw Evidence 및 Execution Result.
- 종합: "지정 포트에서 서비스 종류가 식별되었으며(22 ssh, 23 telnet, 512/513 불확실, 514 tcpwrapped), 신뢰 수준 차이가 기록되었다." 이는 보안 취약점 판단이 아니라 Objective/Expected Result에 대한 평가이다.

## Finding

- Finding 없음.
- 근거: 서비스 종류 관찰(ssh/telnet/exec?/login?/tcpwrapped)은 그 자체로 보안 요구사항 위반을 의미하지 않는다. Finding 판단에 필요한 Security Requirement/평가 기준이 아직 정의되지 않았다.

## Notes

- 서비스 식별(DO-EXT-003)과 애플리케이션/버전 식별(DO-EXT-004)을 혼동하지 않는다.
- 포트가 open이라는 사실과 그 포트의 서비스가 무엇인지는 구분한다.
- 참고: `../objectives.md`의 DO-EXT-003, `../procedures/TP-EXT-003-01.md`, `assessments/README.md`의 Test Case Definition 및 Test Execution Model.
- NIST Relationship: NIST SP 800-115 Section 4.2의 Service Identification 개념을 기반으로 한다.
