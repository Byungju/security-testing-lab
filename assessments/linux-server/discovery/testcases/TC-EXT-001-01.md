# TC-EXT-001-01 Network Reachability Verification

## Test Case ID

TC-EXT-001-01

## Objective

DO-EXT-001 Network Reachability Identification

- 이 Test Case는 DO-EXT-001을 검증하는 첫 번째 Test Case이다.
- DO-EXT-001의 목적은 Known Target에서 평가 위치로부터 대상 네트워크 주소에 대한 도달 가능성을 확인하는 것이며, 이는 이후 DO-EXT-002(Network Port Identification)의 전제 조건이 된다.
- 이 Test Case는 그 목적을 수행 가능한 하나의 평가 단위로 구체화한 것이다.

## Title

Network Reachability Verification

## Purpose

- 대상 Linux Server가 평가 위치에서 네트워크적으로 도달 가능한지 확인한다.
- 도달 가능성 확인 결과를 이후 Discovery Objective(특히 DO-EXT-002)의 전제 조건으로 사용할 수 있도록 기록한다.
- 광범위한 Host Discovery가 아니라, 이미 정의된 Known Target에 대한 도달 가능성 확인에 한정한다.

## Scope

- 포함: 지정된 대상 네트워크 주소에 대한 평가 위치 관점의 도달 가능성 확인.
- 제외: 대상이 아직 정의되지 않은 경우의 광범위한 Host Discovery(Unknown Target 확장), 포트·서비스 식별, 취약점 평가, 보안 구성 평가.
- 이 Test Case는 도달성의 존재 여부와 관찰 방식을 기록하는 데 한정하며, 그 자체로 차단 여부를 확정하지 않는다.

## Target

- 평가 범위에 포함된 Linux Server의 네트워크 주소(예: hostname 또는 IP 주소).
- 대상 주소는 Test Case 수행 시점에 확정하며, 여러 주소가 지정된 경우 각 주소를 구분해 기록한다.

## Assessment Perspective

External Discovery (외부 관점)

- 평가 대상 시스템의 외부에서 관찰한다.
- Known Target에 대한 도달 가능성 확인이며, 광범위한 Host Discovery가 아니다.

## Preconditions

- 대상이 승인된 평가 범위에 포함되어 있어야 한다.
- 대상이 Known Target으로 정의되어 있어야 한다. Unknown Target에 대한 광범위한 Network Discovery는 이 Test Case의 범위가 아니다.
- 평가 위치(외부 관점)가 정의되어 있어야 한다.
- 평가가 승인된 네트워크 경로에서 수행되어야 한다.
- 대상 네트워크 주소가 명확해야 한다.

## Test Method

개념 수준의 검증 의도(Test Intent)이다. 특정 도구나 명령어를 확정하지 않는다.

- 대상 Linux Server의 네트워크 도달 가능성을 승인된 방식으로 관찰하고, 관찰된 결과와 조건을 기록한다.
- 구체적인 수행 절차는 아래 Test Procedure에서 정의한다.
- 도구나 명령은 절차를 수행하기 위한 수단이며, 방법론으로 확정하지 않는다.

## Test Procedure

이 Test Case의 실제 수행 절차는 별도 관리 단위인 Test Procedure에서 정의한다.

- Test Procedure: `../procedures/TP-EXT-001-01.md` (TP-EXT-001-01).
- 이 Test Case는 무엇을 검증하는가, 어떤 조건에서 평가하는가, Expected Result, Evidence Requirements를 정의한다.
- 실제 수행 순서, 관찰 지점, Evidence 수집 방법은 Test Procedure에서 정의한다.
- Procedure Steps, Observation Points, Evidence Collection, Completion Criteria는 `TP-EXT-001-01.md`를 참고한다.

## Expected Result

- 대상 주소에 대한 네트워크 도달 가능성을 확인할 수 있어야 한다.
- 이 Test Case의 Expected Result는 특정 도달/비도달 상태가 아니라, 도달성 관찰과 그 관찰 조건이 기록되는 것이다.
- 어떤 평가 위치에서 어떤 방식으로 도달성을 확인했는지 기록할 수 있어야 한다.
- 도달성이 확인되지 않은 경우, 그 사실과 관찰 조건을 구분해서 기록할 수 있어야 한다.
- 도달 가능성은 ICMP 응답 여부만으로 판단하지 않는다. ICMP 응답, TCP 연결 등 승인된 여러 도달성 관찰 방식이 있을 수 있으며, 어떤 방식으로 관찰했는지를 함께 기록한다.
- 응답이 관찰되지 않은 경우 이를 "도달 불가능"으로 단정하지 않고, "관찰되지 않음(inconclusive)"으로 기록할 수 있어야 한다.

## Evidence Requirements

다음 정보를 포함하는 Evidence를 수집한다.

- Target Address: 도달성을 확인한 대상 주소.
- Assessment Perspective / Location: 어느 평가 위치(외부 관점)에서 관찰했는지.
- Observation Method: 어떤 방식으로 도달성을 관찰했는지.
- Tool: 관찰에 사용한 도구(있는 경우).
- Execution Conditions: 옵션·파라미터 등 실행 조건.
- Observed Result: 관찰된 결과의 요약(예: 어떤 방식에 대해 어떤 응답/연결이 관찰되었는지).
- Timestamp: 관찰 시각.
- Raw Data / Original Observation: 재검토 가능한 원본 관찰 결과.

Evidence는 다음 질문에 답할 수 있어야 한다.

- 무엇을 관찰했는가?
- 어떤 대상에서 관찰했는가?
- 언제 관찰했는가?
- 어떤 평가 관점에서 관찰했는가?
- 어떤 방법으로 수집했는가?
- 원본 데이터를 다시 검토할 수 있는가?

Evidence는 이후 Actual Result와 Assessment Result를 재검토할 수 있는 수준으로 남긴다.

## Actual Result

To be populated during test execution. (테스트 실행 시 채운다.)

- Evidence에서 실제로 관찰된 상태만 기록한다.
- 관찰 사실과 해석을 한 문장에 섞지 않는다.

## Assessment Result

To be populated after evidence analysis. (Evidence 분석 후 채운다.)

- Actual Result를 Objective와 Expected Result 관점에서 해석한다.
- Actual Result의 관찰 사실을 그대로 반복하지 않는다.

## Finding

To be determined after result analysis.

- 모든 Test Case가 Finding을 생성하는 것은 아니다.
- Result와 평가 기준을 통해 보안상 문제가 확인된 경우에만 Finding으로 연결한다.
- 이 Test Case 문서에서는 Finding을 미리 만들지 않는다.

## Notes

- "Reachable"을 단순히 "Ping에 응답한다"와 동일시하지 않는다. ICMP 응답 여부와 모든 네트워크 접근 가능 여부는 다르다.
- 응답이 관찰되지 않았다는 것은 하나의 관찰 결과이며, 그 자체로 "도달 불가능"을 의미하지 않는다.
- 도달성 관찰 결과의 예시 범주는 ICMP response, TCP connectivity, 기타 승인된 도달성 관찰이다. 이 문서는 특정 결과를 가정하지 않는다.
- 도달성 관찰 결과는 최소한 "관찰됨(도달 가능)", "관찰되지 않음(불충분/불명확)", 필요 시 "도달 불가로 판단됨"을 구분해 기록할 수 있어야 한다.
- 실제 도구, 명령어, Evidence, Result, Finding은 이 단계에서 작성하지 않는다.
- 참고: `../objectives.md`의 DO-EXT-001, `assessments/README.md`의 Test Case Definition 및 Test Execution Model.
- NIST Relationship: 이 Test Case는 DO-EXT-001을 계승하며, NIST SP 800-115 Section 4.1 Network Discovery의 개념과 관련된다. Known Target의 도달 가능성 확인은 프로젝트가 평가 흐름에 맞게 구체화한 것이다.
