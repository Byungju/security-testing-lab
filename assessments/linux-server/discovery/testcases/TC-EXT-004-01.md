# TC-EXT-004-01 Application and Version Identification (TCP)

## Test Case ID

TC-EXT-004-01

## Objective

DO-EXT-004 Application and Version Identification

- 이 Test Case는 DO-EXT-004를 검증하는 TCP Test Case이다.
- DO-EXT-004는 식별된 서비스 뒤의 애플리케이션과, 가능한 경우 버전을 식별하는 Objective이다.
- 입력은 DO-EXT-003의 결과(포트-서비스 매핑)이다.

## Title

Application and Version Identification (TCP)

## Purpose

- DO-EXT-003에서 식별된 서비스에 대해, 이를 구현하는 애플리케이션과 버전을 식별한다.
- 식별 결과를 이후 Attack Surface 구성 및 내부 검증(DO-INT-003/004)의 입력으로 사용할 수 있도록 기록한다.

## Scope

- 포함: 관찰된 서비스 포트에 대한 애플리케이션/버전 식별.
- 제외: 취약점 평가, 보안 구성 평가, 포트 스캔/서비스 종류 식별(DO-EXT-002/003), UDP.
- 애플리케이션/버전 식별은 Observation이며, 그 자체로 보안 판단이 아니다.

## Target

- 평가 범위에 포함된 Linux Server의 네트워크 주소(예: hostname 또는 IP 주소).

## Assessment Perspective

External Discovery (외부 관점)

## Preconditions

- 대상이 승인된 평가 범위에 포함되어 있어야 한다.
- DO-EXT-003에서 포트-서비스 매핑이 식별되어 있어야 한다.
- 식별 대상 포트가 Configuration에 명시되어 있어야 한다.
- 사용할 도구(nmap)와 필요한 권한이 확보되어 있어야 한다.
- Evidence를 저장할 위치와 형식이 준비되어 있어야 한다.

## Test Method

개념 수준의 검증 의도(Test Intent)이다. 특정 도구를 방법론으로 확정하지 않는다.

- Version/Application Identification(nmap -sV --version-light): 지정된 각 포트의 서비스에 대해 애플리케이션과 버전 후보를 식별한다.
- 식별 결과는 추정을 포함할 수 있으며, 신뢰 수준(확인/추정/미확인)을 구분한다.
- 대상 포트는 Configuration에 명시된 값만 사용하며, Runner가 임의로 추가하지 않는다.

## Expected Result

- 지정된 각 포트에 대한 애플리케이션과 버전(가능한 경우) 후보가 기록된다.
- 식별 신뢰 수준이 구분되어 기록된다.
- 사용한 방식/도구/옵션/시각과 원본 Evidence가 기록된다.
- 버전을 확정할 수 없는 경우 미확인/추정으로 기록한다.

## Evidence Requirements

- Target / Assessment Perspective / Verification Method / Tool(버전) / Execution Conditions(대상 포트, 옵션, Timeout) / Observed Result(애플리케이션/버전) / Timestamp / Raw Output.

## Actual Result

- 근거 실행: `20261006T161936-DO-EXT-004` (TCP 22,23,512,513,514, nmap -sV --version-light)
- 관찰:
  - `22/tcp open ssh` → OpenSSH 9.8 (protocol 2.0)
  - `23/tcp open telnet` → Linux telnetd
  - `512/tcp open exec?` → 애플리케이션/버전 미확인
  - `513/tcp open login?` → 애플리케이션/버전 미확인
  - `514/tcp open tcpwrapped` → 버전 미확인
  - Service Info: OS: Linux
- 참고: `--version-all` 및 기본 `-sV`는 512/513/514에서 timeout이 발생하여 `--version-light`를 사용했다.
- 원본: `execution/results/20261006T161936-DO-EXT-004/raw/version_scan/`, 요약: 동일 디렉터리 `summary.md`.

## Assessment Result

- Expected Result 관점: 지정 포트에 대한 애플리케이션/버전 후보와 신뢰 수준이 기록되었다. 22/23은 애플리케이션/버전이 식별되었고(OpenSSH 9.8, Linux telnetd), 512/513/514는 미확인으로 구분되어 기록되었다.
- 확인된 범위: 외부 관점에서 22/23의 애플리케이션/버전. 512/513/514는 서비스/버전이 확정되지 않았다.
- 확인되지 않은 범위/한계: tcpwrapped/무응답 포트(512/513/514)는 버전을 확인할 수 없었고, `--version-light`로 인한 탐지 깊이 제한이 있다. 버전은 추정일 수 있어 확인 사실과 구분한다.
- 평가 근거: 위 Raw Evidence 및 Execution Result.
- 종합: "22/23의 애플리케이션/버전이 식별되었고(OpenSSH 9.8, Linux telnetd), 512/513/514는 미확인으로 기록되었다." 이는 보안 취약점 판단이 아니라 Objective/Expected Result에 대한 평가이다.

## Finding

- Finding 없음.
- 근거: 애플리케이션/버전 관찰은 그 자체로 보안 요구사항 위반을 의미하지 않는다. Finding 판단에 필요한 Security Requirement/평가 기준이 아직 정의되지 않았다.

## Notes

- 애플리케이션/버전 식별(DO-EXT-004)과 서비스 종류 식별(DO-EXT-003)을 혼동하지 않는다.
- 버전은 추정일 수 있으며, 확인된 사실과 구분한다.
- 참고: `../objectives.md`의 DO-EXT-004, `../procedures/TP-EXT-004-01.md`, `assessments/README.md`의 Test Case Definition 및 Test Execution Model.
- NIST Relationship: NIST SP 800-115 Section 4.2의 Version Scanning(예: Banner Grabbing) 개념을 기반으로 한다.
